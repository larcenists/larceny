# Notes for working on this repository

This is "accomplice", a fork of Larceny (a Scheme implementation), ported
to 64-bit words on macOS/Apple Silicon and x86-64 Linux.  There are two
kinds of build:

- **Petit Larceny** (Standard-C back end): Scheme compiled to C.  Builds
  on both platforms (`'host: 'macosx-arm64` or `'linux-x86-64`).
- **Native Larceny** (Fence/Cant back end): machine code generated by
  `src/Asm/Fence/pass5p2-arm64.sch` (AArch64, macOS) or
  `src/Asm/Fence/pass5p2-x86-64.sch` (x86-64, Linux), with compiled
  code in a collectable code space (`src/Rts/Sys/code-space.[ch]`).
  The x86-64 back end has 8 MacScheme registers, so Twobit spills more
  than with AArch64's 16; it is tested by `test/Asm/x86-64`
  (`run-encoder-test.sh`, which compares disassemblies against GNU as).
  The old 32-bit Sassy/IAssassin back end is not used.

See `doc/HOWTO-BUILD` for build steps.

## Building

- Never mix build products of different configurations (Petit vs
  native, ...) in one tree: they share paths, and `make` goes by
  timestamps only.  `setup` records the configuration in
  `build-configuration` and refuses a different one; pass `'clean` to
  `setup` to remove the old products (or use separate worktrees).
  The host Scheme is not part of the configuration.
- Racket (`/Applications/Racket v9.3/bin/plt-r5rs --no-prim` on macOS,
  `plt-r5rs --no-prim` on Linux) or an existing Larceny can host the
  build.  Pass build commands to the host in a file, not on stdin (a
  build step consumes stdin).
- `src/Build/bootstrap.sh [--native|--petit] [--racket|--larceny PATH]
  [--clean] [--r7rs]` does a whole build.  By hand: `setup`, ...,
  `build-larceny-files`, then `(build-larceny-heap)`, which runs the new
  binary on the heap script (`src/Build/*-larceny-heap.sch`).
- A Larceny host whose kind differs from the target (e.g. native
  building Petit) loads the build files from source (`'always-source`,
  set automatically), since the tree's `.fasl` files are the target's.
- After building, compile the R7RS/R6RS libraries once:
  `(require 'r7rsmode) (larceny:compile-r7rs-runtime)`.
- The build's make rules treat compiled files as out of date when the
  compiler or assembler sources are newer (`make:tool-files`, set in
  `src/Build/nbuild.sch`), so editing the compiler recompiles the
  libraries at the next `build-heap`.
- The Linux machine is small (about 1.6 GB of memory, one CPU): run one
  build or test suite at a time, and expect a Racket-hosted Petit build
  to take about ten minutes.
- gcc 15 defaults to C23, where `bool` is a keyword; the runtime's
  `bool` is its own int-sized enum, so 64-bit builds use `-std=gnu17`.
- `larceny.bin` is installed read-only.  Never copy over it in place:
  MacOS kills a signed binary modified in place when it starts.  Remove
  it first, or copy to a new file and `mv` it into place.
- `make clean` in `src/Rts` deletes the generated `Shared/arithmetic.c`;
  rerun `build-config-files` afterwards.
- A heap build that fails leaves `larceny.heap` as it was.  A heap may
  need the binary that dumped it (Petit's always do), and the build
  replaces `larceny.bin` before it builds the heap, so each successful
  heap build keeps its binary: `larceny.bin.cur` with `larceny.heap` is
  the last heap built, and `larceny.bin.prev` with `larceny.heap.prev`
  the one before (likewise `petit-larceny.*`).  If the tree's Larceny
  cannot host a build, host it with one of those pairs (a script that
  runs `larceny.bin.prev -heap larceny.heap.prev "$@"`) or with Racket.

## Code generation switches (AArch64; FENCE_INLINE_DEFERRED also x86-64)

Environment variables read when the compiler is loaded, for testing:

- `FENCE_LONG_BRANCHES=1` forces long-branch mode in every code vector
  (normally only in code vectors of more than 8000 MAL instructions).
- `FENCE_INLINE_DEFERRED="timer stack arith imm check satb"` (or `all`)
  emits those kinds of slow paths in line instead of at the end of the
  code vector (see `fence.defer!` in `src/Asm/Fence/pass5p2.sch`).

Set them when building (`bootstrap.sh`) to affect the heap.

The collector clears the registers that the running code does not use
(a mask in each code vector's documentation, made by the assembler; see
`fence.store-register-mask!` in `src/Asm/Fence/pass5p2.sch`).  The
runtime option `-keepregs` keeps them, for debugging and to tell
whether a bug comes from a mask that leaves out a live register.

## Feature markers

Compiled files begin with `#lap(...)` or `#lop(...)` (after `#!fasl` in
`.fasl` files), listing what the code assumes of the system and what it
guarantees; see `src/Lib/Common/code-features.sch`.  When changing code
generation, keep them true:

- Bump the version in `(target fence-arm64 N)` (in
  `assembler-lop-features`, `src/Asm/Fence/pass5p2-arm64.sch`) when the
  calling convention or millicode interface changes incompatibly.
- Add to or remove from the guarantees when barriers change.
- A collector that needs something new of compiled code adds it to
  `system-code-requirements`.

## Testing

- `test/Lib`: `(load "load-all-tests.sch") (run-all-tests)` in a copy of
  the directory.
- Compiler: `test/Compiler`, `(load "run-tests.sch") (run-compiler-tests sanity-switches)`.
- R7RS/R6RS suites: `test/R7RS/Lib/testall` and `testr6rs-larceny`
  (also `MODE=--r6rs ./testr6rs-larceny`, after changing an R6RS
  library: R6RS mode reads libraries with strict R6RS syntax).
- Libraries compiled in separate runs, plain and from a dumped heap:
  `test/R7RS/Separate/run-separate-test.sh` (after changing the
  expander or how libraries are compiled).
- Test the default collector, `-stopcopy`, and `-rrof` (the regional
  collector; its concurrent marking relies on the SATB pre-barrier).
- When piping input into `./larceny` from an interactive shell, note that
  after end of input the console is reopened on `/dev/tty` (the REPL
  waits for the keyboard); without a terminal it falls back to
  `/dev/null`.  Use a timeout in scripts anyway.

## Conventions

- Commit in small chunks, each of which builds and passes its relevant
  tests; say in the commit message what was tested.
- Keep code word-size independent (the runtime is shared with 32-bit
  targets), and keep Petit's behavior unchanged when changing shared code.
- Print a `word` or `s_word` with `"%" PRIxWORD` (also `PRIdWORD`,
  `PRIuWORD`, `PRIXWORD`, in `larceny-types.h`) and a pointer with `%p`.
  The runtime's message functions (`consolemsg`, `panic_exit`, ...) are
  declared `PRINTF_LIKE`, and the arm64 builds compile with `-Wformat`.
- Match the style of surrounding code.
