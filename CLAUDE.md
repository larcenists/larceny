# Notes for working on this repository

This is "accomplice", a fork of Larceny (a Scheme implementation), ported
to 64-bit words on macOS/Apple Silicon.  There are two kinds of build:

- **Petit Larceny** (Standard-C back end): Scheme compiled to C.
- **Native Larceny** (Fence/Cant back end, AArch64): machine code
  generated by `src/Asm/Fence/pass5p2-arm64.sch`, with compiled code in a
  collectable code space (`src/Rts/Sys/code-space.[ch]`).

See `doc/HOWTO-BUILD` for build steps.

## Building

- Never build Petit and native (or builds hosted by different Schemes)
  in the same tree: they write build products to the same paths, and
  `make` goes by timestamps only.  Use separate worktrees, or clean with
  `git clean -fdX` (removes only ignored build products) before switching.
- Racket (`/Applications/Racket v9.3/bin/plt-r5rs --no-prim`) or an
  existing Larceny can host the build.  Pass build commands to the host
  in a file, not on stdin (a build step consumes stdin).
- Native builds have two stages: the host-Scheme stage (`setup` with
  `'native`, ... `build-larceny-files`), then
  `./larceny.bin -stopcopy -heap arm64.heap -- src/Build/arm64-macosx-larceny-heap.sch`.
  `src/Build/bootstrap-arm64-native.sh` does both from Racket.
- After building, compile the R7RS/R6RS libraries once:
  `(require 'r7rsmode) (larceny:compile-r7rs-runtime)`.
- `make clean` in `src/Rts` deletes the generated `Shared/arithmetic.c`;
  rerun `build-config-files` afterwards.

## Testing

- `test/Lib`: `(load "load-all-tests.sch") (run-all-tests)` in a copy of
  the directory.
- Compiler: `test/Compiler`, `(load "run-tests.sch") (run-compiler-tests sanity-switches)`.
- R7RS/R6RS suites: `test/R7RS/Lib/testall` and `testr6rs-larceny`.
- Test both the default collector and `-stopcopy`; for Petit also
  `-rrof` (not yet supported natively).
- When piping input into `./larceny`, use a timeout: after an error at end
  of input the REPL loops forever (see TODO.md).

## Conventions

- Commit in small chunks, each of which builds and passes its relevant
  tests; say in the commit message what was tested.
- Keep code word-size independent (the runtime is shared with 32-bit
  targets), and keep Petit's behavior unchanged when changing shared code.
- Match the style of surrounding code.
